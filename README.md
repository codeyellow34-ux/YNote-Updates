# Y-Note 업데이트 공지

공개 업데이트 안내만 보관하는 독립 저장소입니다. 프로그램 소스·설치파일·메모·백업·개인정보·인증정보·로그를 올리지 않습니다.

## 허용 파일

- `latest.json`: 일반 배포용 공지 (`channel: stable`)
- `test.json`: 테스트 설치본 전용 공지 (`channel: test`)
- `README.md`: 관리 규칙
- `.gitignore`: 허용 파일 외 일반 Git 추가 방지

## 공지 관리

일반 설치본은 `latest.json`만, 테스트 설치본은 `test.json`만 읽습니다. 다른 공지 파일로 자동 전환하지 않습니다. 일반 설치본은 `channel: test` 또는 `test-`로 시작하는 공지 식별자를 거부합니다. 기존 분리 전 설치본은 `latest.json`만 읽으므로 이 파일에 테스트 공지를 올리지 않습니다.

설치파일 제작·검수와 실제 공지 공개를 분리합니다. 사용자가 실제 공지를 띄워 달라고 할 때만 `latest.json`을 활성화합니다. 공개 직전 설치 버전·패치 내용·배포 페이지를 확인하고 공개 후 실제 응답을 확인합니다. 테스트 활성화/비활성화는 `test.json`에서만 합니다. 두 공지는 현재 비활성 상태입니다.

형식은 `schema: 1`, `channel`, `active`, `releaseId`, `version`, `patchNotes`입니다. `active: true`이고 공지 버전이 설치된 4자리 버전보다 높을 때 표시합니다. 새 패치는 더 높은 버전과 새 식별자를 사용합니다. 테스트 식별자는 `test-`로 시작합니다. 공지를 내릴 때 `active: false`로 바꾸며 패치 내용은 빈 배열이어도 됩니다.

UTF-8 64 KiB 이하, 식별자는 영문·숫자·하이픈·밑줄·마침표 80자 이하, 패치 내용은 최대 20개·각 500자·합계 8,000자 이하입니다. 개인 정보나 비공개 작업 내용을 넣지 않습니다. 배포 이동 주소는 프로그램의 고정 페이지를 사용하며 인증 토큰을 추가하지 않습니다.

허용 파일만 개별 변경합니다. `.gitignore`는 웹 업로드나 강제 추가를 차단하지 않으므로 공개 전 파일 목록과 내용을 점검합니다. 커밋 작성자는 GitHub 비공개용 이메일을 사용합니다.
